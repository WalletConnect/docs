---
title: "Payout errors"
sidebarTitle: "Errors"
description: "The error codes the Payouts API returns and what to do about each one."
---

Errors return `{ "code", "message" }`, plus `issues: [{ field, message }]` for validation errors. Branch on `code`.

| HTTP | `code` | What to do |
| --- | --- | --- |
| `400` | `params_validation`, `invalid_params` | Fix the request; `issues` names the field. |
| `400` | `missing_idempotency_key` | Send an [`Idempotency-Key`](/payments/payouts/create-a-payout#idempotency-key). |
| `400` | `unsupported_asset` | Use USDC on a chain from `GET /v1/payout-accounts`. |
| `401` | `missing_api_key`, `invalid_api_key` | Send a valid, unrevoked `wcpo_` key. |
| `403` | `payouts_disabled` | Payouts are off for your account. Reads keep working. |
| `404` | `not_found` | No payout with this ID on your account. |
| `409` | `idempotency_conflict` | This key was used for a different payout. |
| `409` | `payout_not_cancellable` | The payout isn't `requires_action`, so it can't be cancelled. Read it for its current status. |
| `409` | `payout_account_unavailable` | Your payout account isn't set up yet. |
| `503` | `screening_unavailable` | Retry with the same `Idempotency-Key`. |
| `503` | `payout_account_busy` | Retry with the same `Idempotency-Key`. |
| `503` | `payouts_unavailable` | Payouts aren't available. Don't retry. |
| `500` | `internal_error` | Retry; for a payout, with the same `Idempotency-Key`. |
