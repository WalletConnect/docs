Give your AI coding assistant deep, accurate knowledge of the WalletConnect Pay Headless SDK. The **`walletconnect-pay-headless`** [Agent Skill](https://skills.sh) teaches your agent the runtime model, the five seams, the 17-state payment snapshot, and the exact code for the server proxy, wallet connection, and render loop — so it scaffolds a correct integration instead of guessing.

<Note>
  A Skill is a portable package of procedural knowledge an AI agent loads on demand. This one is maintained alongside the SDK in [`WalletConnect/skills`](https://github.com/WalletConnect/skills), so it stays in lockstep with the `@walletconnect/pay-*` packages.
</Note>

## Install

Install the skill into your project with a single command:

<CodeGroup>

```bash npm
npx skills add WalletConnect/skills/walletconnect-pay-headless
```

```bash pnpm
pnpm dlx skills add WalletConnect/skills/walletconnect-pay-headless
```

```bash bun
bunx skills add WalletConnect/skills/walletconnect-pay-headless
```

</CodeGroup>

Once installed, your assistant automatically loads the skill when you ask it to work on a WalletConnect Pay headless checkout. Learn more about the ecosystem at [skills.sh](https://skills.sh).

## Try it

With the skill installed, ask your assistant things like:

- _"Add a WalletConnect Pay headless checkout to my Next.js app."_
- _"Wire the server proxy so my Engine API key stays server-side."_
- _"Render the payment options and confirm step from the snapshot."_
- _"How do I handle the Permit2 approve-and-pay step?"_
- _"Build a framework-neutral checkout with `createPaymentController`."_

## What's included

<CardGroup cols={2}>
  <Card title="The runtime model" icon="diagram-project">
    The headless runtime + host model, the five injectable seams (`Transport`, `WalletProvider`, `Signer`, `Clock`, `Telemetry`), and which ones you wire vs. which the SDK ships.
  </Card>
  <Card title="The snapshot contract" icon="table-list">
    All 17 `PaymentState` values mapped to what to render and which action to call, plus the exact `PaymentSnapshot` fields — the whole UI contract in one table.
  </Card>
  <Card title="Server proxy" icon="server">
    The five Engine routes and the server-side `createEngineClient`, with the guarantee that the API key never reaches the browser.
  </Card>
  <Card title="React / Next.js" icon="react">
    `usePaymentSession` + `<PayAppKitProvider>`, the memoized seam assembly, and the full render switch.
  </Card>
  <Card title="Vanilla JavaScript" icon="js">
    `createPaymentController` with manual `subscribe` and imperative render — framework-neutral.
  </Card>
  <Card title="Custom wallet" icon="wallet">
    Bring your own `WalletProvider` seam and compose the raw `EvmSigningStrategy` / `SolanaSigningStrategy` when you are not using AppKit.
  </Card>
</CardGroup>

Every snippet in the skill is grounded in the [reference checkout](https://github.com/WalletConnect/walletconnect-pay-examples/tree/main/gateway/headless-checkout) and the published SDK types — the same sources as these docs.

## Supported agents

The skill follows the open [Agent Skills](https://skills.sh) specification and works with any compatible assistant, including **Claude Code, Cursor, Codex, GitHub Copilot, Windsurf, Gemini, Cline**, and more.
